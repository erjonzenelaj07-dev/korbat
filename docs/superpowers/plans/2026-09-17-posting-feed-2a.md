# korbat 2a — Posting and Feed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** People can post, reply, quote, like, repost, bookmark, follow, block and mute on the web, read a chronological Following timeline and a public Latest timeline, and open threads and profiles, with blocks enforced in every query and write limits tiered by account age.

**Architecture:** A `social` module inside the API (`apps/api/src/social/`) shaped like the auth module: one repository with every SQL statement on the korbat_api pool, one file per flow, thin routes mounted at `/api` behind the auth module's requireSession, and the architecture test extended to its boundary. Timelines are single Postgres queries with counters kept as columns; the web app renders everything through one post card and one paged list.

**Tech Stack:** Hono 4.13.5, Drizzle 0.45.2, Postgres 16, zod 4.5.4, Expo 57 with expo-router, NativeWind, vitest 4.1.11. No new dependencies.

**Complete code:** every task's full files, commands and observed output are in `docs/superpowers/prompts/posting-feed-2a/`, one prompt per task, generated from a verified dry run. This plan is the map. Where it and a prompt differ, the prompt wins.

**Spec:** `docs/superpowers/specs/2026-09-17-posting-feed-2a-design.md`, including the amendments found by the dry run.

# korbat — Passkeys (1c) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An account signs in with a passkey from a button or the email field's autofill, re-authenticates with it, and manages its passkeys; a passkey added from a stolen session is announced and undone, and credential changes on an account with TOTP need two factors.

**Architecture:** Nine commits: the ground (dependencies, contracts, migration 0010, configuration), the passkey core (stateless challenges, korbat's own checks around SimpleWebAuthn, a software authenticator for tests), session factors with level-2 freshness, token rotation and the lockdown routine, registration and management, sign-in and re-authentication, deletion and export, the web app, the fixes an adversarial review of those seven commits upholds, and the documentation. Each feature starts with a failing test.

**Tech Stack:** Node 24, TypeScript 7 (6 in the Expo app), Hono 4.13, zod 4, drizzle, PostgreSQL 18, Valkey, @simplewebauthn/server 14.0.2 and @simplewebauthn/browser 14.0.0, Expo SDK 57 / expo-router, vitest 4.

**Complete code:** each task's full files, commands and observed output are in `docs/superpowers/prompts/passkeys-1c/NN-<slug>.md`, generated from a verified dry run. This plan is the map. Where it and a prompt differ, the prompt wins.

**Spec:** `docs/superpowers/specs/2026-09-25-passkeys-1c-design.md`.

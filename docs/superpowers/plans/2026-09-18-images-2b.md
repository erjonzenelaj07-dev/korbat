# korbat 2b — Images Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A signed-in person can add up to four described images to a post, reply or quote on the web; everyone who may see the post sees them; stored images are fresh metadata-free WebP files made by a worker that has no network, credentials or capabilities; and integration tests stop touching development data.

**Architecture:** Two Docker volumes and a file protocol replace MinIO: the API streams uploads to `media-uploads` and reads results and files from `media-store`, which it treats as untrusted; the worker reads uploads and writes the store, atomically, with results as the commit point. A `media` module in the API (repository, flows, routes, sweeper) is shaped like the auth and social modules, and serves files after the post's visibility check. The shared `@korbat/media-protocol` package holds the limits, paths, result schema and sniffers.

**Tech Stack:** sharp 0.35.4 (libvips 8.18.6), blurhash 2.0.5, expo-image 57.0.5, Hono 4.13.5, Drizzle 0.45.2, Postgres 16, Redis, zod 4.5.4, Expo 57 with expo-router and NativeWind, vitest 4.1.11.

**Complete code:** every task's full files, commands and observed output are in `docs/superpowers/prompts/images-2b/`, one prompt per task, generated from a verified dry run. This plan is the map. Where it and a prompt differ, the prompt wins.

**Spec:** `docs/superpowers/specs/2026-09-18-images-2b-design.md`, including the amendments found by the dry run.
